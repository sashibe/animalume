# 0005. キャラクター 3 バージョン事前生成方式の採用

## 状況

Animalume の結果画面では、判定された 16 タイプそれぞれにキャラクターを表示する。これは中核体験であり、実装方式の選択肢として以下を比較した：

- **A. 1タイプ1画像**（16枚で固定）
- **B. 確信度で 3 段階バリエーション**（48枚を事前生成）
- **C. 軸別強度反映フルバリエーション**（128枚〜数百枚を事前生成）
- **D. AI リアルタイム生成**（ユーザーごとに独自画像を生成）

CLAUDE.md §1.3 の差別化要素「キャラクター容姿変化 + シェア画像生成」をどこまで踏み込むかの判断。

## 決定

**B. 各タイプ × 3 強度バリエーション（standard / shimmer / quiet）の合計 48 枚を事前生成する方式を採用する。**

ユーザーの確信度（4軸スコアの絶対値平均）に応じて適切なバリエーションを表示する：

| バリエーション | 確信度 | 内容 |
|---|---|---|
| standard | 0.40〜0.75 | 基本イラスト |
| shimmer | 0.75以上 | 表情豊か、モチーフ密度高、彩度高め |
| quiet | 0.40未満 | 控えめな表情、モノトーン寄り、余白多め |

判定ロジックは `src/lib/character.ts` の `pickVariantFromConfidence()` で実装（CLAUDE.md §9.1）。

## 理由

### 採用理由

#### 1タイプ1画像（A）の限界

- 確信度 86% の INTJ と確信度 45% の INTJ に同じビジュアルを出すと、「同じタイプでも内的体験は違う」という Animalume の核心が表現できない
- ADR-0002「タイプは変化する」前提との相性も悪い。変化を可視化したい思想に対して、ビジュアルが固定では矛盾する
- 既存サービス（16personalities など）と差別化できない

#### フルバリエーション（C）の課題

- 軸別強度反映で 4軸 × 2極 × 16タイプ = 128枚、より細かくすれば数百〜数千枚規模
- 制作コスト・運用負荷・品質統制が現フェーズに対して過大
- 16 タイプ間で一貫したアートディレクションを保ちながら数百枚を生成するのは、品質ブレを招く
- Phase 6 以降の検討事項として保留（CLAUDE.md §9.8）

#### AI リアルタイム生成（D）の不採用

CLAUDE.md §11 Out of Scope に明記済み：

- コスト：1 ユーザーあたり画像生成 API 費用が無料モデル（ADR-0004）と整合しない
- 品質ブレ：16 タイプの世界観統一が崩壊するリスクが高い
- 離脱要因：生成待ち時間（数秒〜十数秒）が結果画面の到達率を下げる
- データ価値：「誰もが同じタイプの同じキャラクターを共有できる」ことが、シェア体験のバイラル性に直結する。ユーザーごとに独自画像では「あ、私もそのタイプだ」という共感ポイントが生まれない

#### 3 バリエーションが最小有意差

- 「強い・標準・控えめ」の 3 段階は、人間の知覚的にも有意差を感じる最小単位
- 確信度を 0.40 以下／0.40 〜 0.75／0.75 以上の 3 区間に対応させることで、コードもシンプル
- 最小コスト（48 枚）で「変化が見える」体験を提供できる

### 段階的実装の容易性

CLAUDE.md §9.7 のとおり、未実装タイプは `CharacterImage` コンポーネントが自動的にプレースホルダーにフォールバックする仕組みを持っている。

```typescript
const IMPLEMENTED_TYPES: ReadonlySet<MbtiType> = new Set<MbtiType>([
  'ENFJ',
  'ESTP',
  // 残り14タイプは生成完了次第追加
]);
```

これにより 48 枚を一度に揃える必要がなく、Phase 1 で 2 タイプから始め、メインターゲット層に多いタイプ（ENFP, INFJ, ISTJ など）から段階的に追加できる。MVP-speed-first（CLAUDE.md §4.1）と整合。

## 却下した選択肢

| 選択肢 | 却下理由 |
|---|---|
| A. 1タイプ1画像 | 差別化不足、ADR-0002 思想との不整合 |
| C. フルバリエーション | コスト過大、品質統制困難。Phase 6 で再検討 |
| D. AI リアルタイム生成 | コスト・品質ブレ・離脱要因の三重苦。CLAUDE.md §11 Out of Scope |

## 再検討トリガー

以下のいずれかが満たされた時点で本 ADR の見直しを検討する：

- フルバリエーション化（C）のコスト試算が現実的になった（AI 生成技術の進歩、または社内アーティスト確保）
- ユーザー調査で「軸別の強度差を見たい」というニーズが定量的に確認された
- データライセンス事業が立ち上がり、キャラクター制作予算を割ける財務状況になった

これらは CLAUDE.md §9.8「将来拡張」と連動する。
