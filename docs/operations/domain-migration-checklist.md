# ドメイン切り替え時のチェックリスト

Animalume で新しいドメインを追加・変更する際に、Phase 2 のような
ドメイン分散問題を再発させないためのチェックリスト。

## 事前準備

- [ ] 新ドメインの所有確認（DNS 管理権限）
- [ ] 既存ドメインのトラフィック・SEO 影響の評価
- [ ] Firebase Auth に紐付くユーザーデータへの影響評価

## DNS 設定

- [ ] A レコード / CNAME レコードを Firebase Hosting に向ける
- [ ] TXT レコード（hosting-site=<site名>）で所有権確認
- [ ] 旧ドメインの DNS は維持する（リダイレクト先として残す）

## Firebase Hosting カスタムドメイン設定

- [ ] Firebase Console > Hosting でカスタムドメイン追加
- [ ] **重要**: 旧ドメイン（または www サブドメイン）は「リダイレクトドメイン」として登録
  - 「すべてのリクエストを別のドメインにリダイレクトする」オプションを ON
  - リダイレクト先に新ドメインを指定
- [ ] これを忘れると、両ドメインが独立して動作してしまう

## Firebase Auth 設定

- [ ] Authentication > Settings > 承認済みドメイン に新ドメインを追加
- [ ] 旧ドメインは承認済みドメインから削除しない（リダイレクト前のユーザーに配慮）

## SSL 証明書発行待ち

- [ ] Firebase Hosting で SSL 証明書が「Connected」になるまで待つ（最大24時間）
- [ ] 発行中は HTTPS アクセスで証明書エラーが出る場合あり

## 動作確認

- [ ] シークレットウィンドウで新ドメインへの 301 リダイレクト動作確認
- [ ] 新ドメインでの匿名認証フロー
- [ ] 新ドメインでの履歴保存
- [ ] Google サインインフロー（承認済みドメイン設定の確認）

## 既存ユーザーへの影響

- 旧ドメインの匿名 UID に紐付いた履歴は技術的に救出不可
- 本番運用前なら実害最小
- 本番運用後にドメイン変更する場合は、ユーザーへの事前告知と
  Google サインイン誘導による履歴保護を必ず計画する

## 完了後

- [ ] Phase 2 / 関連 ADR の更新
- [ ] このチェックリストの改善点を追記
