# Question Design / Animalume

> Animalume の問題プール設計指針。
> 80問×2言語＝160問の設計思想・運用ルール・更新プロセスを記述する。
>
> このドキュメントは MVP-speed-first フェーズ時点の方針。
> 運用開始後、弁別力（D 係数）データに基づいて継続的に改善する。

---

## 設計思想

### 1. 状況提示型と二択ハイブリッド

公式 MBTI や 16personalities は Likert スケール（5段階・7段階）を多用するが、
Animalume は**状況提示型の二択**を中核とする。

理由：
- **スワイプ UI に最適**：左右二択がスワイプの方向性と直感的に対応
- **判断の重さが伝わる**：「強くそう思う」「ややそう思う」よりも「私はこっち」を選ぶ方が、診断としての納得感が高い
- **回答時間が安定**：Likert は迷いが発生しやすい、二択は決断が速い
- **データ品質が高い**：Likert は中央値（3 や 4）に偏りがちだが、二択は明確な選好が出る

ただし以下のリスクがあるため、設計で対応：
- **二択強制によるストレス**：両方好きじゃない場合の心理的負担 → 状況提示で「どちらかと言えば」を自然に誘発
- **ニュアンスの取りこぼし**：ユーザーの「中間」が反映されない → 80問の総合スコアで補完

### 2. 状況提示型の利点

「あなたは外向的ですか？」と直接聞くと、社会的望ましさバイアス（social desirability bias）が働く。

代わりに：
> 「大人数の集まりに2時間参加した後の気持ちは？」
> A. もっと盛り上がりたい、二次会にも行きたい
> B. 楽しかったけど、そろそろ一人時間が欲しい

このように**具体的な状況を提示し、その状況での選好**を問う。
これにより：
- バイアスが減る
- 自分の傾向を客観視しやすい
- 「あなたは E ですか I ですか？」より楽しい

### 3. 1軸 = 20問の理由

| 観点 | 設計 |
|---|---|
| 各軸の精度 | 20問あれば十分な解像度 |
| 全体所要時間 | 80問 × 約 5秒 = 6〜7分 |
| 完走率 | 5〜10分が完走しやすい目安、6〜7分は最適 |
| 弁別力分析 | 各軸 20問あれば D 係数で問題改善が可能 |

CLAUDE.md §12.1 の通り、計 40問×2軸（1軸あたり 10問）から開始だったが、
データ品質と精度のバランスを取り、**80問（1軸あたり 20問）に拡張**した経緯がある。

### 4. 「業者っぽくない」言葉選び

CLAUDE.md §2.2 / §10.2 のトーン＆マナーに従う：
- ❌ 「あなたは社交的ですか？」（直接的すぎる）
- ❌ 「人付き合いが得意ですか？」（陳腐）
- ✅ 「初対面の人が多い場では、あなたは…」（状況提示型）

## 4軸の設計

### EI 軸（Extraversion / Introversion）

**測りたい本質**: エネルギーをどこから得るか、社会的場面での疲労パターン

**問題のテーマ例**:
- 社交場面の好み（大人数 vs 少人数 / 一人）
- 初対面・知らない人との接触
- 一人の時間の過ごし方
- 話す・聞くのバランス
- 公的な場での振る舞い
- 内省 vs 行動

**避けるべきテーマ**:
- ❌ 「友達は多いですか？」（友達の数は外向性の本質ではない）
- ❌ 「リーダーシップを取りますか？」（J/T軸との交絡）
- ❌ 「人前で話すのが好きですか？」（不安特性との交絡）

### SN 軸（Sensing / iNtuition）

**測りたい本質**: 情報処理の傾向、現在の事実 vs 可能性・パターン

**問題のテーマ例**:
- 情報の受け取り方（詳細 vs 全体像）
- 説明の仕方（具体例 vs 抽象的概念）
- 興味の対象（事実・実用 vs 理論・可能性）
- 過去の経験への依拠
- 直感・閃きの体験
- 比喩・象徴の使い方

**避けるべきテーマ**:
- ❌ 「現実的ですか？」（社会的望ましさが働く）
- ❌ 「想像力豊かですか？」（自己評価の偏りが大きい）
- ❌ 知能や教養に関わる問い（バイアス源）

### TF 軸（Thinking / Feeling）

**測りたい本質**: 判断の基準、論理整合 vs 価値・調和

**問題のテーマ例**:
- 判断の軸（正誤 vs 善悪）
- 対立場面での反応（論理 vs 共感）
- 意思決定の優先順位（公平性 vs 関係性）
- 批判の受け止め方
- 称賛の受け止め方
- 道徳的ジレンマ

**避けるべきテーマ**:
- ❌ 「冷たい人ですか？」（性別ステレオタイプの再生産）
- ❌ 「感情的ですか？」（同上、ジェンダー差で意味が変わる）
- ❌ 「優しいですか？」（曖昧）

特に TF 軸は**ジェンダー・ステレオタイプとの混同**が起こりやすい。
問題文では男性・女性的とされる属性を直接的に問わない。

### JP 軸（Judging / Perceiving）

**測りたい本質**: 外界との関わり方、構造化 vs 開放性

**問題のテーマ例**:
- 計画の立て方（事前計画 vs 状況対応）
- 決断のタイミング（早く決める vs 余裕を持つ）
- 締切への向き合い方
- 整理整頓の傾向
- 予定変更への反応
- 終わらせる満足 vs 続けることの楽しさ

**避けるべきテーマ**:
- ❌ 「真面目ですか？」（社会的望ましさが強い）
- ❌ 「だらしないですか？」（否定的フレームの強制）
- ❌ 「時間に正確ですか？」（文化差が大きい）

## 弁別力（D 係数）

### 定義

D 係数（Discrimination Index）= 該当軸で高スコアグループと低スコアグループの、
その問題での回答の差。

数式：
```
D = (上位27% の選好率) - (下位27% の選好率)
```

範囲：-1.0 〜 +1.0
- D ≥ 0.4: 非常に良い（理想）
- 0.3 ≤ D < 0.4: 良い（目標値）
- 0.2 ≤ D < 0.3: 改善余地あり（要観察）
- D < 0.2: 弁別力が低い、改訂候補
- D < 0: 軸の方向と逆相関、即改訂

### 目標 KPI

CLAUDE.md §3.2 KPI に基づき：
- **全問で D 係数 ≥ 0.3**

### 測定タイミング

- 月次で集計（Cloud Scheduler）
- 各問題の `stats.discriminationIndex` を更新
- 閾値割れの問題は管理者ダッシュボードでアラート

### 改訂プロセス

1. D 係数が 0.3 を下回る問題を抽出
2. 原因分析（翻訳ニュアンス / 文化差 / 設問の曖昧さ）
3. 候補問題を作成（改訂版）
4. A/B テスト（10%のユーザーに新版を提示）
5. 新版の D 係数が改善していれば、本採用に切り替え
6. 旧版は `archived: true` でアーカイブ

## 問題プールの構造

### ファイル配置

```
src/data/questions/
├── ei-pool.ja.ts    ← E/I 軸 日本語 20問
├── ei-pool.ko.ts    ← E/I 軸 韓国語 20問
├── sn-pool.ja.ts    ← S/N 軸 日本語 20問
├── sn-pool.ko.ts    ← S/N 軸 韓国語 20問
├── tf-pool.ja.ts    ← T/F 軸 日本語 20問
├── tf-pool.ko.ts    ← T/F 軸 韓国語 20問
├── jp-pool.ja.ts    ← J/P 軸 日本語 20問
├── jp-pool.ko.ts    ← J/P 軸 韓国語 20問
└── types.ts         ← Question 型定義
```

### Question 型定義

```typescript
type Question = {
  id: string;                           // 'ei-ja-001'
  axis: 'EI' | 'SN' | 'TF' | 'JP';
  format: 'binary' | 'situation' | 'likert';
  locale: 'ja' | 'ko';
  content: string;                      // 問題文
  optionA: { 
    text: string; 
    weight: number;                     // 通常 -1 または +1
  };
  optionB: { 
    text: string; 
    weight: number; 
  };
  active: boolean;
  difficulty?: 'easy' | 'medium' | 'hard';
  tags?: string[];                      // 'social', 'decision', 'creativity' 等
};
```

### 出題ルール

1. 各診断で 1軸 10問 × 4軸 = **40問を出題**（CLAUDE.md §12.1）
2. 各軸の 20問プールから**ランダムに 10問選択**
3. 出題順は軸ごとにブロック化（EI 10問 → SN 10問 → ... ）するか、ミックスするかは UX 検証中
4. 同一ユーザーが連続で診断する場合、**前回と異なる問題を優先**して出題

## 翻訳の指針

### 日本語 → 韓国語

直訳ではなく、**ネイティブの感覚に合わせた意訳**が必要。

例：
- 日本語: 「自分が間違っていたと気づいたとき」
- 直訳: 「자신이 틀렸다고 깨달았을 때」（不自然）
- 意訳: 「내가 틀렸다는 걸 알게 됐을 때」（自然）

ニュアンスの違い：
- 「気づいた」→「알게 됐다」（受動的なニュアンス）
- 「깨달았다」（能動的、深い気づき）

### 文化差への配慮

- **日本特有の状況**：「お盆」「年末年始」など → 韓国版では「秋夕」「正月」に置き換え
- **韓国特有の状況**：「上下関係」「年功」が強い → 日本版では「年上の人との接し方」程度に和らげる
- **共通可能なもの**：「初対面の人と」「会議で」などは共通で使える

### 翻訳レビュープロセス

1. Claude（または Sori）が初訳
2. **韓国語ネイティブによるレビュー**（CLAUDE.md §13.3 To Be Decided）
3. 数件のテストユーザーで違和感確認
4. 違和感がなければ採用
5. 違和感あれば 1 に戻る

ネイティブレビュアー候補：
- Animalume チーム内の韓国語話者
- 専門翻訳サービス
- フィードバック用 Discord / 友人ネットワーク

## 問題追加・更新のプロセス

### 新規追加

1. CLAUDE.md §2 Product Philosophy / §10.2 Voice に従ったトーン確認
2. 該当軸の本質を測れるか確認
3. ジェンダー・文化バイアスがないか確認
4. 日本語版を作成
5. 韓国語版を作成（または翻訳依頼）
6. プールに追加（`active: true`）
7. 1ヶ月後に弁別力を確認、低ければ改訂または撤退

### 既存問題の改訂

1. D 係数低下の検出（月次レポート）
2. 改訂版の候補を作成
3. A/B テスト（10% のユーザーに新版）
4. 2週間後に新旧の D 係数を比較
5. 新版が改善していれば本採用、旧版を `archived` に

### 撤退

以下の条件で撤退（`active: false`）：
- 改訂を試みても D < 0.3 が続く
- 文化的・社会的に時代遅れになった
- 重複する問題がある

撤退した問題は削除せず、`archived: true` でアーカイブ。
過去の診断結果との互換性を保つため。

## アンチパターン

### 避けるべき問題設計

#### 1. ダブルバレル（複合問題）

❌ 「あなたは社交的で、リーダーシップを取れますか？」
→ 社交性とリーダーシップは別軸。1問で2つ問わない

#### 2. 暗黙の前提

❌ 「人前で発表するのは緊張しますか？」
→ 「人前で発表する機会がある」前提が問題

#### 3. 否定形

❌ 「人と一緒にいるのが好きじゃないですか？」
→ 二重否定が混乱を招く。常に肯定形で問う

#### 4. 専門用語

❌ 「あなたは外向的ですか？」
→ 「外向的」自体が MBTI 用語。問題文で MBTI 用語を使わない

#### 5. 社会的望ましさバイアス

❌ 「あなたは思いやりがありますか？」
→ ほぼ全員が「YES」と答える

#### 6. ジェンダー・ステレオタイプ

❌ 「あなたは感情豊かですか？」
→ 「女性 = 感情豊か」のステレオタイプを再生産する可能性
